## SwipeCell 组件修复

修复 `packages/mote-ui/src/components/swipe-cell/swipe-cell.vue` 两个 bug：

1. **初始挂载偏移未生效**：`offset = ref(offsetFor(position.value))` 在 setup 期读取 `leftRef/rightRef`（此时为 undefined），且 `watch(position)` 非 immediate，导致以 `modelValue='left'/'right'` 挂载时单元格渲染为关闭态（translateX(0)）。修复：`onMounted` + `nextTick` 重算 offset（nextTick 延迟到挂载后、mock 后）。
2. **从展开态拖拽回弹不一致**：`handleTouchEnd` 未跨阈值时硬编码 `offset.value = 0`，导致从 open 态拖回中位时视觉关闭但 `position` 仍为 open、且不发 close。修复：改为 `offset.value = offsetFor(position.value)`（关闭态回 0、展开态回展开宽度）。

验证：swipe-cell 单测 10 通过（新增「初始挂载偏移」「展开态回弹」两用例）；全量 47 文件 / 335 用例通过；`vue-tsc --noEmit` 通过。

测试提示：happy-dom 下 offsetWidth 默认 0，测试需 mock；onMounted 内 nextTick 设置 offset 后，DOM 渲染需再 flush，读样式前用 `flushPromises()` 而非单次 `nextTick()`。

### 补充：左右操作区初始露出的布局 bug（用户实际反馈）

用户反馈「开始左右两边按钮都显示出来了」。根因是 CSS 布局：wrapper 用 `display: flex` 排 `[左][内容][右]`，内容 `flex: 1` 收缩腾位，三者都挤进容器宽度可见。修复：wrapper 改 `position: relative`，内容 `width: 100%`，左/右操作区改 `position: absolute` + `translateX(-100%/100%)` 移出可视区（与 JS 的 offset 模型对齐：offset=0 时两侧隐藏）。纯 CSS 修复，JS 逻辑不变。

## 手势组件 touch → Pointer Events 统一重构（PC 端可拖拽）

**背景**：swipe / swipe-cell / pull-refresh 只绑 touch 事件，PC 浏览器鼠标拖拽无效。picker-column 是 touch+mouse 双绑定，slider 已是 Pointer Events。

**经 grill-me 确定的方案**（Q1-Q7）：统一用 Pointer Events；5 组件统一（slider 不动）；PC 定位=开发预览便利；PullRefresh 保持下拉拖拽语义；抽 `usePointerDrag` composable；`touch-action` 按方向映射（横向 `pan-y`/纵向 `pan-x`）；composable 只管「生命周期 + delta + velocity」，结算各归各组件。

**改动**：
- 新增 `packages/mote-ui/src/composables/use-pointer-drag.ts`：`usePointerDrag(target, { direction, disabled, onStart/onMove/onEnd })`，返回 `{ dragging }`。内部：pointerdown 记录起点 + `setPointerCapture?.()`（happy-dom 无此 API，必须 `?.` 守卫）+ window 上 pointermove/up/cancel 成对绑定解绑 + onBeforeUnmount 兜底 + `watchEffect` 按方向设 `el.style.touchAction`。
- `swipe.vue` / `swipe-cell.vue` / `pull-refresh.vue`：删 touch handler 接 composable，结算逻辑原样搬。swipe-cell 的 `lastTouchAt`→`lastPointerAt`。pull-refresh 的「scrollTop==0 才可下拉」折进 `disabled` getter（读 `rootRef.value?.scrollTop`）。
- `picker-column.vue`：touch+mouse 双绑定迁到 composable，velocity 由 composable 提供，`settleIndex`/`momentum.ts` 不动，代码净减。tap 判定用 `info.clientY`（DragInfo 带 clientX/Y）。

**测试迁移**：swipe/swipe-cell/pull-refresh 的 touch 用例全部改 pointer；picker 补拖拽用例（之前 0 条）+ 各组件补 `touch-action` 落位断言。测试模拟模式：`trigger('pointerdown', {clientX,clientY})` + `window.dispatchEvent(new MouseEvent('pointermove/up', {...}))`（同 slider 既有套路）。全量 47 文件 / 345 用例通过，`vue-tsc` 干净，改动文件 lint 干净。

**坑**：
1. happy-dom 无 `setPointerCapture`，直接调会崩，必须 `?.` 守卫。
2. happy-dom `style.touchAction` 有 getter/setter（映射 `touch-action`），可测。
3. 断言 DOM 文本/样式前要 `await nextTick()`（`window.dispatchEvent` 同步，不触发 Vue flush；原 touch 测试用 `await trigger()` 内部已 flush）。
4. 全量 `eslint .` 会扫到 `docs/.vitepress/.temp/**`（VitePress 生成缓存，未加进 eslint ignores）报 2 万多条——是**预先存在**的问题，非本次引入；CI 无 `.temp` 目录不受影响。本次只对改动文件做 targeted lint（干净）。
5. 本环境 `pnpm` shim 失效（corepack 路径错乱），直跑 `./node_modules/.bin/vitest` 可用。

**后续处理**：全量 `eslint .` 的报错已根治——`eslint.config.mjs` ignores 补 `docs/.vitepress/dist-verify/**` 和 `docs/.vitepress/*.timestamp-*.mjs`（之前只漏了这两个，`.temp` 已在前一步补）；`.gitignore` 补 `docs/.vitepress/dist-verify/`。现在 `eslint .` 干净（exit 0）。
